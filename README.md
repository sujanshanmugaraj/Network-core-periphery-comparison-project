# Do Two Notions of "Core" Agree?
### Core–periphery structure vs. structural cohesion, validated by network robustness

Code, data pipeline and paper for a comparative study of **core–periphery** (k-core, Borgatti–Everett,
Rombach et al.) and **structural-cohesion** (Moody–White k-components) notions of a network "core"
across 8 networks from social, biological and infrastructure domains.

* **RQ1** – How much do CP cores and cohesion cores agree? (Spearman, top-x% Jaccard, AMI)
* **RQ2** – Which node ordering dismantles a network fastest? (robustness index R)
* **RQ3** – Does a rank-hybrid of coreness and cohesion beat both on held-out networks?

## Layout

```
data/raw/            downloaded datasets (not versioned; run the download step)
src/
  datasets.py        loading, cleaning (undirected, simple, LCC), statistics
  coreness.py        k-core, Borgatti–Everett (numba greedy), Rombach 2014 (numba SA)
  cohesion.py        exact k-components / cohesion levels (certificate-accelerated)
  robustness.py      exact robustness curves via union–find; ordering helpers
  agreement.py       Spearman, tie-aware top-x% Jaccard, AMI
  nullmodels.py      degree-preserving double-edge swaps (numba)
  stats.py           Wilcoxon, rank-biserial, bootstrap CI, Holm
  pipeline.py        all experiments (cached, seeded, parallel)
  figures.py         all paper figures
tests/               unit tests (incl. brute-force validation of k-components)
results/tables/      CSV tables used in the paper
results/figures/     PDF + PNG figures
paper/               LaTeX source (IEEEtran), generated tables, bibliography, literature notes, main.pdf
```

```bash
python -m src.make_tables
```

All randomness is seeded (`SEED` in `src/pipeline.py`). Each step caches its results in `results/cache/`.
Delete that folder to recompute from scratch. Approximate runtimes on a 12-thread, 8 GB laptop: scores
about 6 min (dominated by betweenness on the largest networks), null models about 1.5 h (Facebook
about 105 s per randomisation), the networkx benchmark up to a few hours because of its 30-min limits,
and everything else under 5 min. Each worker uses about 600 MB of RAM, so keep `--workers` small on 8 GB machines.

## Main results

| Question | Finding |
|---|---|
| RQ1, node level | k-coreness and cohesion level have Spearman ≥ 0.99 in all 8 networks; BE 0.24–0.54, Rombach 0.73–0.99 |
| RQ1, group level | one k-core can hold many overlapping k-components (fragmentation up to 7.7); absent in degree-preserving nulls |
| RQ2 | cohesion ≈ k-core for dismantling; **cohesive brokerage** beats both in 8/8 networks (up to 44 % lower R) |
| RQ3 | rank hybrids do not beat their best component on held-out networks |
| Method | exact k-component algorithm; `networkx.k_components` can return non-maximal components |

## Compile the paper

`paper/main.tex` (IEEEtran) reads its tables from `paper/tables/` (generated by `src.make_tables`) and its
figures from `../results/figures/`. Locally, with [Tectonic](https://tectonic-typesetting.github.io):

```bash
cd paper && tectonic main.tex
```

or with a TeX distribution: `pdflatex main && bibtex main && pdflatex main && pdflatex main`.
On Overleaf, upload `paper/` plus `results/figures/*.pdf` into a `figures/` folder; the
`\graphicspath` in `main.tex` already lists `figures/`.
